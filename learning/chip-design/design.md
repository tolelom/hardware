# 칩 설계 학습 트랙 설계서

최종 갱신: 2026-11-09

---

## 1. 목표와 범위

CPU와 NPU를 Verilog로 설계하고, 작은 설계를 Tiny Tapeout(TT) 셔틀로 제출해 실리콘으로 받습니다.
출발점은 디지털 논리이고 Verilog 경험은 없습니다.

범위에 포함:
- 디지털 논리(조합·순차 회로, FSM)
- Verilog. 합성 가능한 SystemVerilog 부분까지
- 시뮬레이션 검증과 합성 리포트(셀 수, 타이밍) 읽기
- TT 제출 흐름(템플릿, GitHub Actions 하드닝, GDS)
- FPGA 검증. 테이프아웃 직전 단계에서만

범위에서 제외:
- 아날로그·혼성 신호 설계
- 고수준 HDL(Chisel, Amaranth, SpinalHDL). CPU 단계를 마친 뒤 두 번째 바퀴로 둡니다
- 로컬 OpenLane 하드닝. M4의 디스크·메모리 여유로는 PDK와 OpenLane 이미지를 둘 수 없습니다
- 상용 EDA(Vivado, Quartus 등)

CPU와 NPU는 하위 프로젝트로 나눕니다. 이 설계서는 트랙 골격과 CPU 테이프아웃까지 다룹니다.
NPU는 CPU 단계를 마친 뒤 별도 설계서로 씁니다.

## 2. 진행 구조

0단계에서 칩이 되는 흐름 전체를 한 번 끝까지 돌려 층 구성을 먼저 봅니다.
1단계부터는 그 층을 아래에서부터 채웁니다.

```
Verilog → 시뮬레이션 → 합성(Yosys) → 배치·배선(OpenROAD, TT Actions) → GDS → 셔틀 → 칩
          [1~4단계에서 주로 다룸]      [0단계에서 보고, 5단계에서 다시 씀]
```

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0. 지도 | TT Verilog 템플릿으로 카운터를 시뮬레이션, 합성, Actions 하드닝, GDS 보기까지 진행. 제출하지 않음 | Actions 통과, GDS 렌더 확인, 흐름의 층마다 입력과 출력을 표로 정리, TT 공식 자료로 타일 셀 용량과 타일당 가격 확인 |
| 1. 조합 회로 | 게이트, mux, 디코더, 가산기, ALU | 테스트 통과, 합성 셀 수 기록 |
| 2. 순차 회로 | 플립플롭, 레지스터, 카운터, FSM | 테스트 통과, 클록 경계 동작을 파형으로 확인 |
| 3. 데이터패스 | 레지스터 파일, ALU와 레지스터 연결, 메모리 인터페이스 | 테스트 통과, 합성 셀 수 기록 |
| 4a. CPU | 단일 사이클 RV32I 서브셋. 면적 제약 없이 시뮬레이션에서 동작. 레지스터 파일은 별도 모듈로 분리 | RISC-V 테스트 프로그램 통과, 레지스터 파일과 나머지의 셀 수를 나눠 기록 |
| 4b. 비교 | SERV, PicoRV32를 읽고 4a와 구조·셀 수 비교 | 비교표 |
| 4c. 축소 | 4a를 0단계에서 확인한 타일 예산에 맞게 축소(비트 직렬 데이터패스, RV32E, 레지스터 파일 구현 교체 등) | TT 템플릿에서 Actions 통과 |
| 5. 테이프아웃 | 4c를 FPGA에서 검증한 뒤 TT 셔틀 제출 | 제출 완료 |
| 6. NPU | 별도 설계서 | 별도 설계서 |

단계마다 개념은 하나씩 다룹니다. 한 단계 안에서도 개념이 여럿이면 실습을 나눕니다.

4a단계는 명령어 묶음 순서로 실습을 나눕니다. 묶음마다 테스트를 먼저 통과시키고 다음 묶음을 더합니다.

| 순서 | 명령어 묶음 |
|---|---|
| 1 | R형 산술·논리(add, sub, and, or, xor, slt 등) |
| 2 | I형 즉치 산술과 lui, auipc |
| 3 | 로드·스토어 |
| 4 | 분기와 jal, jalr |

## 3. 도구

| 용도 | 도구 | 설치 |
|---|---|---|
| 시뮬레이터 | Icarus Verilog, Verilator | Homebrew |
| 합성 | Yosys | Homebrew |
| 테스트벤치 | cocotb | 트랙 폴더의 Python venv |
| 파형 보기 | Surfer | 공식 macOS 배포본. Homebrew에 없음 |
| 하드닝 | OpenLane(TT 템플릿의 GitHub Actions) | 설치 없음 |
| RISC-V 툴체인 | riscv64-elf-gcc | 4a단계에서 Homebrew로 설치 |
| FPGA | 오픈소스 툴체인이 지원하는 iCE40·ECP5 계열 | 5단계 전에 기종을 정해 구입 |

TT 템플릿이 cocotb 테스트를 쓰므로 0단계부터 같은 테스트 방식을 씁니다.

## 4. 폴더 구성

```
learning/chip-design/
  README.md        트랙 소개, 단계표, 도구 설치 방법
  design.md        이 문서
  requirements.txt cocotb 버전 고정
  stages/
    01-comb/
      rtl/         Verilog 소스
      test/        cocotb 테스트와 Makefile
      notes.md     확인한 동작, 실행 결과, 합성 셀 수
    02-seq/
    ...
```

- 단계마다 `make test`(시뮬레이션), `make lint`(Verilator lint), `make synth`(Yosys 셀 수 리포트)를 둡니다.
- TT 제출용 설계(0, 4c, 5단계)는 TT 템플릿으로 만든 별도 GitHub 저장소에 둡니다. TT Actions가 저장소 단위로 돌기 때문입니다. 이 폴더의 notes.md에서 그 저장소를 가리킵니다.
- 파형 파일(VCD, FST)과 빌드 산출물은 커밋하지 않습니다.

## 5. 진행 방식

- 실습 전에 그 실습이 답할 질문과 전체 흐름을 먼저 맞춥니다.
- 개념은 실행 결과로 보입니다. 파형, 일부러 깨뜨린 테스트, 코드 두 벌의 합성 셀 수 비교를 씁니다.
- 테스트를 먼저 쓰고 RTL을 씁니다.
- notes.md에는 확인한 것만 적습니다. 해보지 않은 것은 "확인 필요", 모르는 것은 "모름"으로 남깁니다.

---

## 6. 검증 기준

모든 RTL에 아래를 적용합니다.

- cocotb 테스트 통과
- Verilator lint(`-Wall`) 경고 0
- Yosys 합성 성공. 래치가 추론되지 않음

CPU(4a 이후)는 위에 더해 RISC-V 테스트 프로그램을 시뮬레이션에서 통과합니다.
테이프아웃 설계(5단계)는 위에 더해 FPGA에서 같은 테스트 프로그램이 동작합니다.
