## 1. 이 보드는 무엇인가

겉모습

- 손가락 한 마디 크기
- USB-C 포트 1개
- 작은 버튼 2개(B, R)
- 칩 위에 RP2040이라고 적힌 스티커. 칩 각인은 확인 불가

칩 자료는 칩 설계사가, 보드 자료는 보드 회사가 냅니다. 블로그·포럼 같은 2차 자료는 힌트로만 쓰고 아래 두 자료에서 확인합니다.

## 2. 코드를 어떻게 넣나

### 하드웨어가 제어하는 부트 순서 (2.7절, 128쪽)

1. 전원이 들어오고 RUN 핀이 high. RUN이 low면 칩은 리셋 상태로 멈춤
2. 내장 레귤레이터가 코어 전원(DVDD) 안정까지 대기
3. 전원 투입 상태 머신 시작
   - 링 오실레이터 기동. clk_sys와 clk_ref가 약 6.5MHz로 동작
   - 리셋 컨트롤러, XIP, 메모리, 버스, 프로세서가 리셋에서 풀림
   - 코어 0과 코어 1이 bootrom 실행 시작

여기까지는 사용자 코드를 보지 않습니다. 어떤 코드를 실행할지는 bootrom이 정합니다.

### bootrom

| 항목 | 내용 |
| --- | --- |
| 위치 | 0x00000000 |
| 크기 | 16kB |
| 수정 | 불가. 실리콘 제조 때 고정 |
| 소스 | https://github.com/raspberrypi/pico-bootrom |
| 버전 | 1, 2, 3이 칩 리비전 B0, B1, B2에 대응 |
| 내용 | 부트 순서, 코어 1 대기, USB 부트로더(UF2, PICOBOOT), flash 함수, 부동소수점·비트·메모리 함수 |

CPU는 리셋 직후 항상 bootrom부터 실행합니다. bootrom은 지울 수 없으므로 flash에 잘못된 코드를 넣어도 USB 모드로 돌아올 수 있습니다.

### 프로세서가 제어하는 부트 순서 (2.8.1절, 129쪽, Figure 15)

코어 1은 잠들고 코어 0이 아래 순서로 확인합니다.

| 순서 | 확인 | 결과 |
| --- | --- | --- |
| 1 | watchdog scratch에 SRAM 코드 표시가 있는가 | 있으면 SRAM 코드로 점프 |
| 2 | flash CSn 핀이 low인가 | low면 flash 부트를 건너뛰고 USB 모드 |
| 3 | flash 앞 256바이트의 CRC32가 맞는가 | 맞으면 그 256바이트(boot2)를 실행 |
| 4 | 3이 실패한 채로 0.5초가 지났는가 | 지나지 않았으면 flash 읽기 설정을 바꿔 3을 재시도, 지났으면 USB 모드 |

USB 모드에서는 칩이 RPI-RP2라는 USB 드라이브로 보이고, UF2 파일을 끌어다 놓으면 파일에 적힌 주소에 따라 flash나 SRAM에 씁니다.

### 버튼 회로

```
칩 56번(QSPI_SS) ── QSPI_CSN ──┬── flash U3 1번 핀(CS)
                               │
                             저항
                               │
                         RP2040_BOOT ── BOOT 버튼(B) ── GND

3V3 ── R5 ──┬── 칩 26번(RUN)
            ├── C2 ── GND
            ├── RESET 버튼(R) ── GND
            └── TP1, TP6
```

| 버튼 | 연결 | 누르면 |
| --- | --- | --- |
| B | QSPI_CSN을 저항을 거쳐 GND로 | CSn low. 부팅 순간에 눌려 있으면 USB 모드 |
| R | RUN을 GND로 | 칩이 리셋 상태로 멈춤. 떼면 2.7절 순서부터 다시 시작 |

bootrom은 부팅할 때 CSn을 한 번 읽습니다. 프로그램이 실행 중일 때 B만 누르면 아무 일도 일어나지 않습니다. USB 모드로 들어가는 순서는 다음과 같습니다.

1. B를 누른 채 유지
2. R을 눌렀다 뗌. B를 누른 채 USB 케이블을 꽂아도 같음
3. B를 뗌

flash에 유효한 코드가 없으면 버튼 없이도 0.5초 뒤 USB 모드로 들어갑니다.

BOOT 쪽 저항이 하는 일

| 상황 | CSn을 잡고 있는 것 | 버튼을 누르면 |
| --- | --- | --- |
| 부팅 순간 | 칩 내부의 약한 풀업 | 버튼 쪽이 이겨 low로 읽힘 |
| 프로그램 실행 중 | flash와 통신하는 칩 출력 | 칩 출력과 GND가 저항을 사이에 두고 연결돼 단락 전류가 제한됨 |

## 3. 어디서 실행되나

| 메모리 | 시작 주소 | 크기 | 전원을 끄면 | 근거 |
| --- | --- | --- | --- | --- |
| ROM | 0x00000000 | 16kB | 유지 | 2.6.1절 |
| SRAM | 0x20000000 | 264kB | 사라짐 | 2.6.2절 |
| flash | 0x10000000 | 2MB | 유지 | 2.6.3절, 회로도 U3 |

flash는 칩 밖의 별도 부품이라 크기가 데이터시트에 없습니다. 회로도의 U3는 GD25Q16CEIG이고, GD25Q 계열 명명 규칙으로 16Mbit(2MB)입니다. 2.6.3절의 16MB는 칩이 flash에 쓰는 주소 창의 최대 크기입니다.

flash에서 부팅하려면 맨 앞 256바이트가 boot2여야 합니다. boot2는 붙어 있는 flash 칩에 맞게 XIP를 설정하는 작은 프로그램이고, 끝 4바이트에 CRC32가 붙어야 합니다. 칩이나 보드가 제공하지 않으므로 코드를 넣는 쪽이 준비합니다.

| | SRAM | flash |
| --- | --- | --- |
| 실행 전에 필요한 것 | 프로그램 | 프로그램과 boot2 |
| 전원을 뽑으면 | 사라짐 | 유지 |
| 실행 속도 | 칩 내부라 빠름 | XIP 캐시(16kB)에 의존 |
| 크기 한도 | 264kB | 2MB |

결정: 최종 목표는 flash, 첫 실행은 SRAM. flash로 바로 가면 boot2와 프로그램 중 어느 쪽이 틀렸는지 가를 수 없습니다. SRAM에서 프로그램을 먼저 검증하면 flash로 옮길 때 바뀌는 것은 boot2 하나입니다.

PC와 비교

| | PC | RP2040 |
| --- | --- | --- |
| 꺼져도 남는 저장소 | SSD | flash |
| 작업용 메모리 | DRAM | SRAM |
| 실행 방식 | SSD에서 DRAM으로 복사 후 실행 | flash에서 복사 없이 실행(XIP), 또는 SRAM에 올려 실행 |
| 캐시 | CPU 캐시(SRAM) | flash 앞 XIP 캐시 16kB |

SRAM은 PC의 DRAM 자리에 있지만, 재료는 PC의 CPU 캐시와 같습니다. DRAM과 달리 refresh가 없고 빠르며 셀이 커서 용량이 작습니다. 캐시와 달리 내용은 프로그램이 정하고 주소로 직접 접근합니다.

## 4. 전원이 들어오면 어디부터 실행하나

USB 모드는 코드를 받는 단계이고, 받은 코드는 대상 주소에 따라 다른 경로로 실행됩니다.

| UF2 대상 | 받은 뒤 | 실행 경로 |
| --- | --- | --- |
| flash (0x10000000~) | 일반 리셋 | Figure 15의 flash 부트 경로, boot2 |
| SRAM (0x20000000~) | watchdog 리셋 | Figure 15의 watchdog 경로, SRAM 코드로 점프 |

SRAM 프로그램은 받은 블록 중 가장 낮은 주소에서 시작합니다(2.8.4.2절, 144쪽). 이 주소는 UF2 파일에 담기고, UF2 파일은 빌드에서 나오므로 링커 스크립트가 정합니다.

watchdog 부트가 넘기는 값(2.8.1.1절, 130쪽)

| scratch | 값 |
| --- | --- |
| 4 | 매직 넘버 0xb007c0d3 |
| 5 | 시작 주소 XOR 매직 |
| 6 | 스택 포인터 |
| 7 | 시작 주소 |

4와 5는 값이 유효한지 확인하는 데 쓰입니다. RAM UF2로 부팅할 때 bootrom이 스택 포인터에 넣는 값은 데이터시트에 적혀 있지 않습니다.

스택 포인터가 필요한 곳

- C 함수: 지역 변수와 돌아갈 주소를 스택에 저장
- 인터럽트·폴트: CPU가 레지스터 8개를 자동으로 스택에 저장. 코드에 push가 없어도 발생

시작 주소의 첫 바이트는 CPU가 명령어로 읽습니다. 그 자리에 데이터나 문자열이 있으면 정의되지 않은 명령어로 HardFault가 나거나, 유효한 명령어로 해석돼 의미 없는 코드를 실행합니다.

정리

1. bootrom은 UF2에 담긴 가장 낮은 주소로 점프
2. 그 주소의 첫 바이트는 명령어
3. 첫 코드는 C 함수보다 먼저 스택 포인터를 설정한 뒤 main 호출

이 첫 코드를 시작 코드라고 합니다. C 함수는 스택 포인터가 이미 설정돼 있다고 가정하고 컴파일되므로 시작 코드는 어셈블리로 씁니다. 시작 코드를 0x20000000 맨 앞에 두는 일은 링커 스크립트가 맡습니다.

### 링커 스크립트 (`ld/sram.ld`)

링커는 함수 이름이 아니라 섹션 이름으로 배치합니다. 시작 코드를 전용 섹션 `.start`에 넣고, 링커 스크립트에서 그 섹션을 가장 먼저 나열합니다.

| 출력 섹션 | 담는 것 | 비고 |
| --- | --- | --- |
| .start | 시작 코드 | `KEEP`으로 `--gc-sections` 제거 방지 |
| .text | 코드 | `*(.text*)`. `-ffunction-sections`가 함수마다 `.text.이름` 섹션을 만듦 |
| .rodata | 문자열, const 전역 | |
| .data | 초기값 있는 전역 | 적재기가 초기값을 실행 위치에 바로 씀 |
| .bss | 초기값 없는 전역 | 파일에 담기지 않음(NOBITS). 시작 코드가 0으로 채움 |

시작 코드에 넘기는 심볼

| 심볼 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `__stack_top` | `ORIGIN(SRAM) + LENGTH(SRAM)` = 0x20042000 | SP 초기값 |
| `__bss_start`, `__bss_end` | .bss의 시작과 끝. 4바이트 정렬 | 0으로 채울 구간 |

스택은 push할 때 SP를 먼저 4 줄이고 쓰므로, 첫 값은 영역 바로 바깥인 0x20042000입니다. 코드와 전역은 아래에서 위로, 스택은 위에서 아래로 자랍니다. 둘이 부딪쳐도 경고는 없습니다.

`ASSERT(_start == ORIGIN(SRAM), ...)`가 시작 코드의 위치를 링크 단계에서 확인합니다. 섹션 이름이 틀려 시작 코드가 맨 앞에서 밀리면 링크가 실패합니다.

### 시작 코드 (`src/start.S`)

1. `ldr r0, =__stack_top`, `mov sp, r0`. Thumb의 ldr은 sp를 목적지로 받지 않음
2. `__bss_start`부터 `__bss_end` 직전까지 4바이트씩 0을 씀. 비어 있으면 첫 비교에서 탈출
3. `bl main`
4. main이 돌아오면 그 자리에서 무한 루프

.bss 채우기를 C로 쓰면 gcc가 최적화로 `memset` 호출로 바꿀 수 있고, `-nostdlib`라 링크가 실패합니다.

### 빌드와 검사

```
start.S, main.c ─ gcc ─> .o ─ ld + sram.ld ─> .elf ─ picotool uf2 convert ─> .uf2
```

uf2는 ELF에서 바로 만듭니다. ELF에 적재 주소가 들어 있어 주소를 링커 스크립트 한 곳에만 적습니다. bin에서 만들 때 `-o`를 빠뜨리면 기본값 0x10000000(flash)으로 들어갑니다.

`make check`는 `tools/check_uf2.py`로 2.8.4.2의 RAM 전용 바이너리 조건을 확인합니다.

- 모든 블록의 매직 넘버와 payload 256바이트
- family id 0xe48bff56(RP2040)
- 모든 블록이 0x20000000~0x20042000 안
- 가장 낮은 블록 주소가 `_start`

링커 스크립트의 ORIGIN을 0x10000000으로 바꿔 빌드하면 picotool이 family id 0xe48bff57을 붙이고, 검사가 실패합니다.

### 이전 트랙과 다른 점

`rp2040-baremetal/`의 SRAM 빌드와 비교한 결과입니다.

| 항목 | 이전 트랙 | 이 트랙 |
| --- | --- | --- |
| 0x20000000의 내용 | 벡터 테이블 두 워드(0x20042000, 0x20000009) | 시작 코드 |
| 맨 앞 8바이트의 실행 | Thumb으로 movs r0,#0 / movs r0,#4 / movs r1,r1 / movs r0,#0이 되어 무해하게 지나감 | 해당 없음 |
| .bss | 채우는 코드 없음. 전역 변수가 없어 증상 없음 | 시작 코드가 0으로 채움 |
| uf2 변환 | bin + `-o 0x20000000` | ELF에서 바로 |

### 작성 전 점검

| 함정 | 증상 |
| --- | --- |
| 어셈블리 섹션에 `"a"` 플래그 누락 | 메모리에 올라가지 않는 섹션이 되어 bin에서 빠짐. 빌드는 통과 |
| `--gc-sections`인데 시작 코드 섹션을 보호하지 않음 | 링커가 섹션을 지움. `KEEP()` 또는 `ENTRY()`로 방지 |
| 심볼 주소에 Thumb 비트를 직접 더함 | 빠뜨려도 빌드는 통과하고 칩에서만 실패. `.thumb_func`로 처리 |
| .bss 경계 정렬 누락 | 4바이트씩 채우는 루프가 정렬 위반으로 멈추거나 끝을 지나침 |
| 전역 변수 없이 시험 | .data와 .bss 처리가 틀려도 증상 없음 |
| 섹션 이름 `.text.startup` | gcc가 main을 같은 이름의 섹션에 넣음 |
| `.cpu cortex-m0plus`, `.thumb` 누락 | M0+에 없는 명령이 걸러지지 않음 |

## 5. 무엇으로 확인하나

### 보드의 LED (회로도)

| LED | 칩 연결 | 켜는 방법 |
| --- | --- | --- |
| RGB2 빨강 | GPIO17 (28번 핀) | low |
| RGB2 초록 | GPIO16 (27번 핀) | low |
| RGB2 파랑 | GPIO25 (37번 핀) | low |
| PWR | 연결 안 됨 | 전원이 들어오면 켜짐 |
| RGB1 (NeoPixel) | 데이터 GPIO12, 전원 GPIO11 | 정해진 타이밍의 직렬 데이터 |

RGB2는 3V3 → LED → 저항 → GPIO 구조라 GPIO가 low일 때 켜집니다(active low). 첫 확인 수단은 GPIO 하나로 움직이는 RGB2 빨강입니다.

### 레지스터

| 블록 | 레지스터 | 주소 | 값 | 근거 |
| --- | --- | --- | --- | --- |
| RESETS | RESET, 원자적 clear 별칭 | 0x4000c000 + 0x3000 | bit 5 IO_BANK0, bit 8 PADS_BANK0 | 2.14, 2.1.2 |
| RESETS | RESET_DONE | 0x4000c008 | 두 비트가 1이 될 때까지 대기 | 2.14 |
| IO_BANK0 | GPIO17_CTRL | 0x40014000 + 0x04 + 17×8 = 0x4001408c | FUNCSEL(bit 4:0) = 5, SIO | 2.19.2, 2.19.6 |
| SIO | GPIO_OUT_SET | 0xd0000014 | 1 << 17 | 2.3.1 |
| SIO | GPIO_OE_SET | 0xd0000024 | 1 << 17 | 2.3.1 |
| SIO | GPIO_OUT_XOR | 0xd000001c | 1 << 17 | 2.3.1 |

주변장치 레지스터는 주소에 0x1000(XOR), 0x2000(set), 0x3000(clear)을 더한 별칭이 있어 읽기-수정-쓰기 없이 비트를 바꿀 수 있습니다(2.1.2). PADS_BANK0은 기본값(출력 허용, 입력 허용, 풀다운)을 그대로 쓰고 리셋만 풉니다.

순서

1. IO_BANK0, PADS_BANK0 리셋 해제 후 RESET_DONE 대기
2. GPIO17_CTRL의 FUNCSEL을 SIO로
3. GPIO_OUT_SET으로 high(꺼짐)를 먼저 정한 뒤 GPIO_OE_SET으로 출력 켜기. GPIO_OUT 기본값이 0이라 순서가 바뀌면 출력을 켜는 순간 LED가 켜짐
4. GPIO_OUT_XOR와 지연 루프로 깜빡임

레지스터 포인터와 지연 루프 변수는 volatile입니다. 빼면 컴파일러가 쓰기와 루프를 지웁니다.

판정은 깜빡임으로 합니다. 패드 풀다운(PDE 기본값 1) 때문에 active low LED는 코드 없이도 희미하게 켜질 수 있습니다.

### 결과

- B를 누른 채 R을 눌렀다 떼서 BOOTSEL 모드 진입
- uf2를 RPI-RP2 드라이브에 복사하자 드라이브와 USB 장치가 사라짐
- 빨강 LED가 1초에 1~2번 깜빡임

지연 루프 20만 번을 한 바퀴 10사이클 안팎으로 잡으면 약 200만 사이클이고, 부팅 직후 클럭 약 6.5MHz에서 0.3초 남짓입니다. 켜짐과 꺼짐을 합친 주기 0.6초 정도와 앞뒤가 맞습니다. 클럭은 재지 않았습니다.
