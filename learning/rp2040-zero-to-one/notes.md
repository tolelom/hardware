## 1. 이 보드는 무엇인가

겉모습

- 손가락 한 마디 크기
- USB-C 포트 1개
- 작은 버튼 2개(B, R)
- 칩 위에 RP2040이라고 적힌 스티커. 칩 각인은 확인 불가

칩 자료는 칩 설계사가, 보드 자료는 보드 회사가 냅니다. 블로그·포럼 같은 2차 자료는 힌트로만 쓰고 아래 두 자료에서 확인합니다.

## 2. 코드를 어떻게 넣나

### 하드웨어가 제어하는 부트 순서 (2.7절, 128쪽)

1. 전원이 들어오고 RUN 핀이 high. RUN이 low면 칩은 리셋 상태로 멈춤
2. 내장 레귤레이터가 코어 전원(DVDD) 안정까지 대기
3. 전원 투입 상태 머신 시작
   - 링 오실레이터 기동. clk_sys와 clk_ref가 약 6.5MHz로 동작
   - 리셋 컨트롤러, XIP, 메모리, 버스, 프로세서가 리셋에서 풀림
   - 코어 0과 코어 1이 bootrom 실행 시작

여기까지는 사용자 코드를 보지 않습니다. 어떤 코드를 실행할지는 bootrom이 정합니다.

### bootrom

| 항목 | 내용 |
| --- | --- |
| 위치 | 0x00000000 |
| 크기 | 16kB |
| 수정 | 불가. 실리콘 제조 때 고정 |
| 소스 | https://github.com/raspberrypi/pico-bootrom |
| 버전 | 1, 2, 3이 칩 리비전 B0, B1, B2에 대응 |
| 내용 | 부트 순서, 코어 1 대기, USB 부트로더(UF2, PICOBOOT), flash 함수, 부동소수점·비트·메모리 함수 |

CPU는 리셋 직후 항상 bootrom부터 실행합니다. bootrom은 지울 수 없으므로 flash에 잘못된 코드를 넣어도 USB 모드로 돌아올 수 있습니다.

### 프로세서가 제어하는 부트 순서 (2.8.1절, 129쪽, Figure 15)

코어 1은 잠들고 코어 0이 아래 순서로 확인합니다.

| 순서 | 확인 | 결과 |
| --- | --- | --- |
| 1 | watchdog scratch에 SRAM 코드 표시가 있는가 | 있으면 SRAM 코드로 점프 |
| 2 | flash CSn 핀이 low인가 | low면 flash 부트를 건너뛰고 USB 모드 |
| 3 | flash 앞 256바이트의 CRC32가 맞는가 | 맞으면 그 256바이트(boot2)를 실행 |
| 4 | 3이 실패한 채로 0.5초가 지났는가 | 지나지 않았으면 flash 읽기 설정을 바꿔 3을 재시도, 지났으면 USB 모드 |

USB 모드에서는 칩이 RPI-RP2라는 USB 드라이브로 보이고, UF2 파일을 끌어다 놓으면 파일에 적힌 주소에 따라 flash나 SRAM에 씁니다.

### 버튼 회로

```
칩 56번(QSPI_SS) ── QSPI_CSN ──┬── flash U3 1번 핀(CS)
                               │
                             저항
                               │
                         RP2040_BOOT ── BOOT 버튼(B) ── GND

3V3 ── R5 ──┬── 칩 26번(RUN)
            ├── C2 ── GND
            ├── RESET 버튼(R) ── GND
            └── TP1, TP6
```

| 버튼 | 연결 | 누르면 |
| --- | --- | --- |
| B | QSPI_CSN을 저항을 거쳐 GND로 | CSn low. 부팅 순간에 눌려 있으면 USB 모드 |
| R | RUN을 GND로 | 칩이 리셋 상태로 멈춤. 떼면 2.7절 순서부터 다시 시작 |

bootrom은 부팅할 때 CSn을 한 번 읽습니다. 프로그램이 실행 중일 때 B만 누르면 아무 일도 일어나지 않습니다. USB 모드로 들어가는 순서는 다음과 같습니다.

1. B를 누른 채 유지
2. R을 눌렀다 뗌. B를 누른 채 USB 케이블을 꽂아도 같음
3. B를 뗌

flash에 유효한 코드가 없으면 버튼 없이도 0.5초 뒤 USB 모드로 들어갑니다.

BOOT 쪽 저항이 하는 일

| 상황 | CSn을 잡고 있는 것 | 버튼을 누르면 |
| --- | --- | --- |
| 부팅 순간 | 칩 내부의 약한 풀업 | 버튼 쪽이 이겨 low로 읽힘 |
| 프로그램 실행 중 | flash와 통신하는 칩 출력 | 칩 출력과 GND가 저항을 사이에 두고 연결돼 단락 전류가 제한됨 |

## 3. 어디서 실행되나

| 메모리 | 시작 주소 | 크기 | 전원을 끄면 | 근거 |
| --- | --- | --- | --- | --- |
| ROM | 0x00000000 | 16kB | 유지 | 2.6.1절 |
| SRAM | 0x20000000 | 264kB | 사라짐 | 2.6.2절 |
| flash | 0x10000000 | 2MB | 유지 | 2.6.3절, 회로도 U3 |

flash는 칩 밖의 별도 부품이라 크기가 데이터시트에 없습니다. 회로도의 U3는 GD25Q16CEIG이고, GD25Q 계열 명명 규칙으로 16Mbit(2MB)입니다. 2.6.3절의 16MB는 칩이 flash에 쓰는 주소 창의 최대 크기입니다.

flash에서 부팅하려면 맨 앞 256바이트가 boot2여야 합니다. boot2는 붙어 있는 flash 칩에 맞게 XIP를 설정하는 작은 프로그램이고, 끝 4바이트에 CRC32가 붙어야 합니다. 칩이나 보드가 제공하지 않으므로 코드를 넣는 쪽이 준비합니다.

| | SRAM | flash |
| --- | --- | --- |
| 실행 전에 필요한 것 | 프로그램 | 프로그램과 boot2 |
| 전원을 뽑으면 | 사라짐 | 유지 |
| 실행 속도 | 칩 내부라 빠름 | XIP 캐시(16kB)에 의존 |
| 크기 한도 | 264kB | 2MB |

결정: 최종 목표는 flash, 첫 실행은 SRAM. flash로 바로 가면 boot2와 프로그램 중 어느 쪽이 틀렸는지 가를 수 없습니다. SRAM에서 프로그램을 먼저 검증하면 flash로 옮길 때 바뀌는 것은 boot2 하나입니다.

PC와 비교

| | PC | RP2040 |
| --- | --- | --- |
| 꺼져도 남는 저장소 | SSD | flash |
| 작업용 메모리 | DRAM | SRAM |
| 실행 방식 | SSD에서 DRAM으로 복사 후 실행 | flash에서 복사 없이 실행(XIP), 또는 SRAM에 올려 실행 |
| 캐시 | CPU 캐시(SRAM) | flash 앞 XIP 캐시 16kB |

SRAM은 PC의 DRAM 자리에 있지만, 재료는 PC의 CPU 캐시와 같습니다. DRAM과 달리 refresh가 없고 빠르며 셀이 커서 용량이 작습니다. 캐시와 달리 내용은 프로그램이 정하고 주소로 직접 접근합니다.

## 4. 전원이 들어오면 어디부터 실행하나

USB 모드는 코드를 받는 단계이고, 받은 코드는 대상 주소에 따라 다른 경로로 실행됩니다.

| UF2 대상 | 받은 뒤 | 실행 경로 |
| --- | --- | --- |
| flash (0x10000000~) | 일반 리셋 | Figure 15의 flash 부트 경로, boot2 |
| SRAM (0x20000000~) | watchdog 리셋 | Figure 15의 watchdog 경로, SRAM 코드로 점프 |

SRAM 프로그램은 받은 블록 중 가장 낮은 주소에서 시작합니다(2.8.4.2절, 144쪽). 이 주소는 UF2 파일에 담기고, UF2 파일은 빌드에서 나오므로 링커 스크립트가 정합니다.

watchdog 부트가 넘기는 값(2.8.1.1절, 130쪽)

| scratch | 값 |
| --- | --- |
| 4 | 매직 넘버 0xb007c0d3 |
| 5 | 시작 주소 XOR 매직 |
| 6 | 스택 포인터 |
| 7 | 시작 주소 |

4와 5는 값이 유효한지 확인하는 데 쓰입니다. RAM UF2로 부팅할 때 bootrom이 스택 포인터에 넣는 값은 데이터시트에 적혀 있지 않습니다.

스택 포인터가 필요한 곳

- C 함수: 지역 변수와 돌아갈 주소를 스택에 저장
- 인터럽트·폴트: CPU가 레지스터 8개를 자동으로 스택에 저장. 코드에 push가 없어도 발생

시작 주소의 첫 바이트는 CPU가 명령어로 읽습니다. 그 자리에 데이터나 문자열이 있으면 정의되지 않은 명령어로 HardFault가 나거나, 유효한 명령어로 해석돼 의미 없는 코드를 실행합니다.

정리

1. bootrom은 UF2에 담긴 가장 낮은 주소로 점프
2. 그 주소의 첫 바이트는 명령어
3. 첫 코드는 C 함수보다 먼저 스택 포인터를 설정한 뒤 main 호출

이 첫 코드를 시작 코드라고 합니다. C 함수는 스택 포인터가 이미 설정돼 있다고 가정하고 컴파일되므로 시작 코드는 어셈블리로 씁니다. 시작 코드를 0x20000000 맨 앞에 두는 일은 링커 스크립트가 맡습니다.
