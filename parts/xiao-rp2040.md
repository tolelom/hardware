# Seeed XIAO RP2040

부품 기준 문서. 확인된 것만 적는다. 모르는 것은 "모름"으로 남긴다.
최종 갱신: 2026-09-07

## 스펙

출처: [Seeed Studio Wiki, XIAO RP2040](https://wiki.seeedstudio.com/XIAO-RP2040/)

| 항목 | 값 |
|---|---|
| MCU | Raspberry Pi RP2040, Cortex-M0+ 듀얼코어, 최대 133 MHz |
| RAM | 264 KB SRAM |
| Flash | 외부 QSPI 2 MB. Winbond W25Q080 계열 |
| 노출 GPIO | 11 (전부 PWM 가능) |
| 아날로그 입력 | 4 |
| 인터페이스 | I2C ×1, UART ×1, SPI ×1 |
| USB | Type-C |
| 배터리 충전 | 없음. Plus 변종에만 있다 |
| 온보드 | 유저 LED, 전원 LED, RGB LED, 리셋 버튼, 부트 버튼 |
| SWD | 패드 노출됨 |

Plus 변종(미보유): 디지털 I/O 26(메인 11 + 납땜 패드 15), I2C ×2, 배터리 관리 내장.

## 보유 현황

| 품목 | 수량 | flash id |
|---|---|---|
| XIAO RP2040 | 1 | `0x4150345236383019` |

flash id는 `picotool info -a`가 보고하는 값이다. 부트로더 모드의 USB 시리얼은
`E0C9125B0D9B`로 다른 값이다. 앱 모드의 USB 시리얼은 확인 필요.

## 제약

확인된 것만 적는다.

1. 노출 GPIO가 11개뿐이다. 이것이 이 보드의 결정적 제약이다.
   TKL 키보드 매트릭스는 6행 17열이라 23핀이 필요하다.
   따라서 이 보드로는 87키 전체 매트릭스를 프로토타입할 수 없다.
   11핀으로 만들 수 있는 최대 매트릭스는 5×6, 30키 규모다.
   펌웨어와 스캔 로직 검증에는 충분하지만 핀 배정표 전수 검증은 불가능하다.
2. WiFi와 Bluetooth가 없다. RP2040 칩 자체에 무선이 없다.
   Pico W의 무선은 CYW43439라는 별도 칩이며 XIAO RP2040에는 없다.
3. 온보드 배터리 충전 회로가 없다. 배터리 구동에는 외부 회로가 필요하다.
4. 아날로그 입력이 4개다. nRF52840의 6개보다 적다.

## 툴체인

| 스택 | 상태 |
|---|---|
| 베어메탈 (gcc, ld, objcopy, picotool) | 검증됨. SRAM 적재로 UART 출력까지 확인. [rp2040/](../rp2040/) |
| picotool | 검증됨. 2.3.0을 소스 빌드해 PICOBOOT로 플래시 읽기와 `load -x` 적재·실행까지 확인 |
| Arduino | 확인 필요. 공장 펌웨어가 arduino-pico 4.4.0 산출물이라 동작은 하나 직접 빌드는 안 함 |
| CircuitPython / MicroPython | 확인 필요 |
| Pico SDK (C/C++) | SDK 2.3.0 클론으로 boot2 레퍼런스 빌드까지 확인. 보드에 굽는 것은 확인 필요 |
| QMK / Vial | 확인 필요. RP2040은 QMK 공식 지원 플랫폼이지만 XIAO 보드 정의 유무는 확인 안 함 |

호스트 도구는 Ubuntu에 갖춰져 있다. `arm-none-eabi-gcc` 13.2, `cmake` 3.31,
`gdb-multiarch` 15.1, `picotool` 2.3.0(`~/.local/bin`)이다. `openocd`는 미설치다.
Windows 데스크톱의 WSL 두 distro에는 없다. 2026-08-31에 확인했다.

## USB 식별과 부트로더

보드를 Ubuntu에 연결해 확인했다.

| 모드 | USB ID | 인터페이스 | 저장장치 |
|---|---|---|---|
| 앱 | `2e8a:000a` | CDC 시리얼 | 없음 |
| 부트로더 | `2e8a:0003` | 대용량 저장장치 + PICOBOOT(vendor) | `RPI-RP2` 128 MB |

앱 모드의 USB ID는 펌웨어가 정하는 값이라 고정이 아니다. USB를 쓰지 않는
펌웨어를 구우면 앱 모드에서 USB 장치가 뜨지 않는다.

부트로더 모드는 인터페이스를 둘 노출한다. 대용량 저장장치는 UF2를 받는
쓰기 전용 창구이고 플래시를 읽어낼 수 없다. 읽기는 vendor 인터페이스인
PICOBOOT로만 되며 `picotool`이 이 경로를 쓴다.

부트로더 진입은 B(부트)를 누른 채 R(리셋)을 한 번 누르거나, B를 누른 채 USB를 다시 연결한다.

| 항목 | 값 |
|---|---|
| 버전 | UF2 Bootloader v3.0 |
| Board-ID | `RPI-RP2` |

Board-ID가 RP2040 공용이라 Pico 등 다른 RP2040 보드용 UF2도 부트로더가 그대로 받는다.
핀 배치가 다르므로 XIAO 전용 빌드인지는 파일 쪽에서 확인해야 한다.

이 부트로더는 RP2040 칩의 ROM에 있다. 칩에 내장 플래시가 없어 외부 QSPI 플래시를 쓰는
구조라, 플래시 내용과 무관하게 B 버튼으로 항상 부트로더에 들어간다.

저장장치 볼륨 크기는 부트로더가 만들어 보이는 값이고 실제 플래시 2 MB와 무관하다.

공장 출하 펌웨어는 RGB LED를 순환시킨다. 앱 모드에서 CDC 시리얼은 뜨지만
붙어 있는 동안 받은 것은 없었다. USB CDC는 호스트가 포트를 열기 전에 쓴 것을
버리므로 이 관측만으로 출력이 없다고 단정할 수 없다.

펌웨어의 정체와 플래시 변화 여부는 백업 폴더의 README에 있다.

## 온보드 LED

출처는 Seeed 핀아웃 그림이다. 빨강·초록·파랑은 베어메탈 펌웨어로 직접 제어해 확인했다.

| LED | GPIO | 극성 |
|---|---|---|
| RGB 빨강 | 17 | LOW가 켜짐 |
| RGB 초록 | 16 | LOW가 켜짐 |
| RGB 파랑 | 25 | LOW가 켜짐 |
| WS2812 | 12 | 데이터 핀. 직접 구동은 확인 필요 |

위키 본문 요약은 WS2812를 Plus 전용으로 적고 있으나 핀아웃 그림에는 일반 버전에도 있다.
백업본에 `PIOProgram.cpp` 경로가 남아 있는 것과 앞뒤가 맞는다.

LED로 펌웨어 동작을 판정할 때 걸리는 것이 둘 있다.

리셋 직후 PADS 레지스터 기본값 `0x56`에 PDE가 서 있어 풀다운이 켜져 있다.
코드를 올리지 않아도 세 LED가 희미하게 켜진다. 전원 LED도 빨간색이라 켜짐만으로는
구별되지 않는다. 켜짐이 아니라 깜빡임으로 판정한다.

OE와 OUT은 별개다. `SIO_GPIO_OE_SET`을 빼면 값을 써도 핀까지 나가지 않는다.
이때 풀다운이 이겨 희미하게 켜진 상태로 남으므로 코드가 안 도는 것과 구별되지 않는다.

## 디버깅 경로

- SWD 패드가 노출돼 있다. 출처는 Seeed 위키.
- Raspberry Pi Debug Probe가 RP2040 SWD용 장비다. 실제 연결은 안 해봤다.
- UART0 은 GPIO0 이 TX, GPIO1 이 RX 다. 보드 실크스크린으로는 D6 과 D7 이고
  D0·D1 이 아니다. 실크스크린의 D 번호와 GPIO 번호는 다르다. 베어메탈 3단계에서
  Raspberry Pi Debug Probe 의 UART 브리지에 물려 확인했다. 115200 과 1 Mbaud
  둘 다 깨지지 않았다.
- 호스트가 Ubuntu일 때 dialout과 plugdev 그룹만으로 접근되는 것은 CDC 시리얼(`/dev/ttyACM*`)뿐이다.
  PICOBOOT는 raw USB라 장치 노드에 쓰기 권한이 필요하고, 기본값은 root 전용이다.
  `picotool`의 `udev/60-picotool.rules`를 `/etc/udev/rules.d/`에 넣어야 일반 사용자로 쓸 수 있다.

## PIO

RP2040에는 PIO(Programmable I/O) 스테이트머신이 있다.
임의 프로토콜을 CPU 개입 없이 사이클 정확하게 구현하는 블록이다.
공장 펌웨어가 이미 PIO를 쓴다. 백업본에 `PIOProgram.cpp` 경로가 남아 있다.
GPIO12의 WS2812가 유력한 대상이다. 대조는 안 했다.

직접 다룰 용도는 아직 정하지 않았다.
