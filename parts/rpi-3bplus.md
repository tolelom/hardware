# Raspberry Pi 3 Model B+

부품 기준 문서. 확인된 것만 적는다. 모르는 것은 "모름"으로 남긴다.
용도 미정이다. 아래 후보 비교에서 결정한 뒤 `devices/`로 승격한다.
상시 용도와 별개로 일시 용도 하나가 배정돼 있다:
LDAC 송신 동글의 1~2단계 검증. [devices/ldac-dongle/README.md](../devices/ldac-dongle/README.md) 참조.
최종 갱신: 2026-09-01

## 제약

확인된 것만 적는다.

1. 이더넷이 USB 2.0 버스를 공유한다. 기가비트로 표기되지만 USB 2.0의 480 Mbps를 통과하므로
   실효 대역폭이 그 아래로 제한된다. USB 저장장치를 동시에 쓰면 서로 잠식한다.
2. RAM이 1 GB다. 컨테이너를 여러 개 올리기에는 빠듯하다.
3. microSD로 부팅한다. SD 카드가 이 보드의 가장 흔한 고장 지점이다.
   상시 구동 용도로 쓰면 마모를 고려해야 한다.
4. 역할이 Mac Mini 2대와 겹친다. 이것이 이 보드의 가장 큰 문제다.
   컨테이너로 돌리면 되는 것은 전부 Mac Mini가 더 잘한다.
   RPi가 이기는 것은 GPIO와 물리 인터페이스, 그리고 앱 서버와 독립적으로 살아 있는 것 둘뿐이다.
5. 3.5인치 디스플레이의 실제 인터페이스와 모델을 모른다. 쓰려면 실물 확인이 먼저다.

## 툴체인과 디버깅 경로

| 항목 | 상태 |
|---|---|
| Raspberry Pi OS / Debian | 확인 필요. 현재 SD에 무엇이 들어 있는지 모른다 |
| SSH 접속 | 확인 필요 |
| UART 콘솔 (GPIO 14/15) | 확인 필요. Debug Probe의 UART 포트로 가능해 보이나 안 해봤다 |

이 보드는 최근에 켜본 기록이 없다. 상태 자체가 미확인이다.

## 용도 후보 비교

기준은 두 축이다. 배움이 있는가, 끝나면 실제로 쓰는가.
여기에 필터가 하나 더 붙는다. Mac Mini로 하면 안 되는 이유가 있는가.

| # | 후보 | 배움 | 쓰임 | RPi여야 하는가 |
|---|---|---|---|---|
| A | 3.5인치 LCD 서버 상태 대시보드 | 낮음 | 중간 | 부분적. 물리 화면은 RPi만 가능 |
| B | PB2 개발 지원 장비. 시리얼 콘솔과 TFTP/NFS 부트 서버 | 중간에서 높음 | 높음 | 부분적. Mac Mini나 WSL로도 되지만 전용기 가치가 있다 |
| C | GPIO 물리 장치. 센서와 제어 | 중간 | 용도 미정 | 예 |
| D | 레트로 게임기, 미디어 | 낮음 | 중간 | 아니오 |
| E | 홈 DNS 분리. Pi-hole 등 | 낮음 | 높음 | 예. 앱 서버와 독립이 핵심 |

### B가 배움에서 앞서는 이유

TFTP로 커널을 받고 NFS를 루트로 마운트해 부팅하는 것은 임베디드 개발의 표준 워크플로다.
PB2 로드맵 4단계(커널과 디바이스 트리)부터 커널을 반복해 바꿔 넣게 되는데,
그때마다 SD 카드를 뽑았다 꽂으면 시간이 갈린다.
이 구성을 갖추는 것 자체가 브링업 경험의 일부다.

다만 TFTP/NFS 서버는 WSL이나 Mac Mini에서도 돌아간다.
RPi를 쓰는 근거는 보드 옆에 상시 켜져 있는 전용기라는 것뿐이고, 그것은 편의지 필연이 아니다.

### E가 실사용에서 앞서는 이유

DNS가 앱 서버에 얹혀 있으면 서버를 재부팅할 때 집 인터넷이 같이 죽는다.
Mac Mini 마이그레이션이 진행 중인 상황에서는 실제로 겪는 문제다.
DNS를 별도 저사양 기기로 빼는 것은 합리적인 분리다.

### 반론

Mac Mini 2대를 이미 운영 중인데 RPi를 상시 구동으로 추가하면 관리 대상이 하나 는다.
백업과 모니터링, OS 업데이트가 따라붙는다. microSD 마모라는 새 고장 모드도 생긴다.
"쓰면 좋겠다"로 켜는 것은 이 비용을 무시하는 것이다.

### 현재 권고

B와 E를 겸용한다. 상시 켜져 있는 저사양 유틸기 하나로 묶는다.
둘 다 자원을 거의 안 먹어 1 GB에서 공존하고, 상시 구동이라는 성격이 같다.
LCD(후보 A)는 이 위에 상태 표시로 얹을 수 있다.

착수 시점은 PB2 로드맵 4단계 도달 이후다. 그 전에는 B의 필요가 생기지 않는다.
E만 먼저 하는 것은 배움이 거의 없어 이 묶음의 목적에 맞지 않는다.

이 결정은 아직 확정이 아니다. 내용을 더 정한 뒤 `devices/`로 승격한다.
