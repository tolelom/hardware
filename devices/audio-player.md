# 휴대형 오디오 플레이어 계획

얇은 계획서다. 상세 설계는 pocket-beagle2 저장소의 `applications.md`에 있다.
작업 사본은 WSL `~/pocket-beagle2/applications.md`.
부품 기준 문서: [parts/pocketbeagle2.md](../parts/pocketbeagle2.md)
최종 갱신: 2026-08-30

## 무엇을 만드나

PocketBeagle 2로 microSD 음원을 재생하는 독립형 휴대 플레이어를 만든다.
유선 출력이 기본이고 USB 가젯 입력과 무선 송신을 나중에 얹는다.

## 상태

아직 시작할 수 없다. 두 가지가 동시에 막고 있다.

| 막는 것 | 내용 |
|---|---|
| I2S DAC 없음 | 부품이 없어 첫 단계인 소리 내기 자체가 불가능하다 |
| 브링업 미완 | PB2 로드맵이 1f(SD에 처음 쓰기) 미착수다. 리눅스가 아직 자체 빌드로 안 뜬다 |

이 기기는 브링업이 학습에서 실사용으로 전환되는 지점이다.
로드맵 4단계(커널과 디바이스 트리)에 도달해야 McASP를 다룰 수 있다.

## 왜 PocketBeagle 2인가

- McASP0의 전송 클럭과 수신 클럭이 따로 나오고 데이터 라인이 4개라 전이중 구성에 여유가 있다
- 배포 이미지 커널이 `PREEMPT_RT`다. 실시간 패치가 들어가 오디오 지연에 유리하다
- `BQ21040` 리튬 충전기와 `VBAT` 입력이 온보드라 별도 전원 회로를 만들 필요가 없다
- 브링업을 이미 이 보드로 하고 있어 밑단 지식이 그대로 이어진다

## 배우는 것과 쓰는 것

배우는 것: McASP와 I2S 코덱 연결, 클럭 구조, ALSA, 최소 루트파일시스템 구성,
부팅 시간 단축, 배터리 전원 관리.

쓰는 것: 휴대용 플레이어다. 실사용 가치는 개인 취향에 달렸다. 스마트폰으로도 되기 때문이다.
가치가 확실한 쪽은 그다음 단계인 이펙터다.

## 핵심 지표

이 프로젝트가 어려운 지점은 둘이다.

1. 부팅 시간. 배포판 이미지는 로그인까지 오래 걸린다.
   전원을 넣고 재생까지 수 초 안에 도달하지 못하면 기기가 아니라 리눅스가 도는 보드에 머문다.
2. DAC 클럭 구조. 마스터 클럭을 SoC가 줄지 DAC가 줄지에 따라 지터와 음질이 갈린다.

## 지금 없는 것

| 항목 | 비고 |
|---|---|
| I2S DAC 보드 | 없다. 이것이 없으면 1단계도 시작 못 한다. 출력 음질이 이 선택에 좌우된다 |
| 헤드폰 앰프 | 없다. DAC 출력만으로는 임피던스 높은 헤드폰을 못 구동한다 |
| SPI LCD | 라파용 3.5인치가 있으나 PB2 연결 가능 여부는 모름 |
| 로터리 인코더, 버튼 | 없다 |
| 리튬 배터리 | 없다 |
| USB 소켓 (USB1 배선용) | 확장 단계에서 필요하다 |
| Bluetooth 동글 | 확장 단계에서 필요하다. LDAC 인코딩은 리눅스가 하므로 일반 컨트롤러면 된다 |

## 단계

`applications.md`의 단계표를 그대로 쓴다. 판정 기준만 여기서 구체화한다.

| # | 단계 | 판정 기준 |
|---|---|---|
| 0 | PB2 브링업 로드맵 4단계 도달 | 디바이스 트리로 비활성 주변장치 하나를 살린다 |
| 1 | 소리 내기 | DAC 연결 후 McASP로 재생되어 헤드폰에서 소리가 난다 |
| 2 | 플레이어 | 화면 없이 ssh로 파일 탐색과 재생 제어가 된다 |
| 3 | UI | SPI LCD와 인코더로 보드 단독 조작이 된다 |
| 4 | 부팅 단축 | 전원 인가부터 재생까지 수 초 이내. 로드맵 7단계와 같은 작업이다 |
| 5 | 전원 | 배터리로 동작하고 잔량이 표시된다 |
| 6 | 확장 | USB 가젯 입력으로 USB DAC로 인식되거나, 무선 송신이 된다 |

## 그만둘 조건

- PB2 브링업이 1f에서 막히면 여기까지 오지 못한다. 브링업이 선행이고 그쪽이 먼저 판정된다.
- I2S DAC를 연결했는데 4단계에서 수 초 목표에 못 미치면 휴대 기기를 포기한다.
  거치형 네트워크 플레이어로 목표를 낮춘다. 그쪽은 부팅 시간이 중요하지 않다.

## 이펙터

`applications.md`에 악기용 이펙터 계획이 함께 있다.
플레이어 다음 순서로 명시돼 있고, 플레이어에서 확립하는 McASP 설정과 코덱 연결,
클럭 구조를 그대로 물려받는다.

이펙터는 왕복 지연 10 ms 이하가 목표다.
ADC와 DAC가 모두 있는 코덱, 그리고 악기용 입력 버퍼 회로가 추가로 필요하다.
계획서는 [bass-effector.md](bass-effector.md)로 승격됐다.

6단계(무선 송신)는 [LDAC 송신 동글](ldac-dongle.md)의 최종 형태와 같은 기능이다.
