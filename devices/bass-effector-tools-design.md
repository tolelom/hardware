## 1. 목표와 범위

하드웨어 측정 전에 회로와 기구를 도구로 검증한다. 도구는 셋이다.

| # | 도구 | 답하는 질문 |
|---|---|---|
| 1 | 잡음 예산 | 입력 경로와 출력 경로 중 어느 쪽이 T7 바닥을 정하는가. 부품별 기여는 얼마인가 |
| 2 | BLOCKS에서 SPICE 생성, 몬테카를로 | 시뮬레이션이 회로 기준 파일과 같은 값을 쓰는가. 공차와 어댑터 전압 범위에서 레일·패드·출력 스윙 여유가 남는가 |
| 3 | 기구 검사 | 패널 부품이 서로, 가장자리와, 케이스 안에서 간섭하지 않는가. 타공 도면과 기판 가용 영역은 무엇인가 |

범위에 포함:
- `gen_schematic.py`의 `BLOCKS`를 읽는 SPICE 생성기와 기존 `spice/*.cir` 6개의 이전
- 잡음 모델이 있는 범용 op-amp 부분회로와 잡음 예산 스크립트
- 몬테카를로 구동 스크립트
- 기구 기준 파일과 검사·도면 스크립트
- 각 도구의 단위 테스트

범위에서 제외:
- PCB 레이아웃. 2단계 검증 뒤 최종 기판 설계에서 다룬다. 도구 3은 기판 가용 영역 외곽선까지만 낸다
- 회로 값 변경. 도구 결과가 변경을 요구하면 고칠 블록·부품·값과 근거를 제시하고, 회로 기준 파일 수정은 회로 설계자가 한다
- 열 해석, KiCad ERC 자동화

### 1.1 도구 1의 출발점

회로 설계 12절의 잡음 손계산은 입력 버퍼와 패드만 다룬다. 출력단(블록 E) 잡음은 계산되지 않았다.
데이터시트 값으로 어림한 출력단 잡음은 다음과 같다(시뮬레이션 전 추정).

| 원천 | 출력 기준 nV/√Hz |
|---|---|
| OPA2992 전압 잡음 7nV/√Hz × 게인 5.7 | 39.9 |
| R8 10k 열잡음 × R7/R8 4.7 | 60.5 |
| R7 47k 열잡음 | 27.9 |
| 합 | 77.7 |

A 가중으로 약 -98.9dBu(A)이고, DAC 다이내믹 레인지 120dB를 출력 풀스케일 +17.2dBu에 적용한 바닥 -102.8dBu보다
높다. 이 추정이 맞으면 출력 쪽 합산 바닥(약 -97.4dBu(A))이 입력 쪽(칩 값 기준 약 -100.8dBu(A))보다 크고,
설계서 4.5절의 입력 개선 경로는 효과가 작다. 도구 1이 이 추정을 확정한다.

## 2. 파일 배치

```
effector/hardware/
  gen_schematic.py          BLOCKS (회로 기준, 기존)
  gen_spice.py              BLOCKS -> spice/generated/block_<문자>.cir
  enclosure.py              기구 기준과 검사·도면 (도구 3)
  tests/                    unittest. python3 -m unittest discover effector/hardware/tests
  spice/
    models.inc              다이오드·BJT·MOSFET·스위치 모델 카드 (기존 .cir에서 모음)
    opamp_rr.inc            기존
    opamp_rr_noise.inc      잡음원을 더한 op-amp 부분회로
    lt1054_behavioral.inc   기존 doubler.cir의 스위치 더블러를 부분회로로
    generated/              gen_spice.py 출력. 손으로 고치지 않는다. 커밋한다
    *.cir                   테스트벤치. 소스·해석·meas만 두고 부품은 generated/를 include
    noise_budget.py         도구 1
    monte_carlo.py          도구 2 몬테카를로
  enclosure/                도구 3 출력 (SVG, 보고서)
```

파이썬은 표준 라이브러리만 쓴다. DXF 출력이 필요해지면 그때 `ezdxf`를 더한다. ngspice는 M4에서
`brew install ngspice`로 설치한다.

## 3. 도구 2: BLOCKS에서 SPICE 생성

### 3.1 출력 형식

블록마다 평면 넷리스트 파일 하나를 낸다. 노드 이름은 BLOCKS 넷 이름을 소문자로 바꾼 것이고 GND는 0이다.
노드 이름이 전역이라 테스트벤치는 필요한 블록 파일을 include하고, include하지 않은 블록의 넷은 소스나 부하로
직접 구동한다. 파일 머리에 생성 시각이 아니라 `gen_schematic.py`의 BLOCKS 내용 해시를 적어 재생성 여부를
비교할 수 있게 한다.

### 3.2 소자 매핑

| BLOCKS 심볼 | SPICE | 핀 대응 |
|---|---|---|
| Device R | `R` | 1, 2 |
| Device C, C_Polarized | `C`. 값은 첫 토큰("1000u 25V" -> 1000u) | 1, 2 |
| Device D, D_Schottky, D_Zener | `D` + models.inc 모델(1N4148, 1N5819, DZ12, DZ15) | KiCad 1=캐소드, 2=애노드. SPICE는 애노드 먼저 |
| Device LED | `D` + 적색 LED 모델 | 위와 같다 |
| Transistor_BJT 2N3904, 2N3906 | `Q` | BLOCKS 1=E, 2=B, 3=C. SPICE는 C B E |
| Transistor_FET IRF9540N | 부분회로: LEVEL 1 PMOS + 바디 다이오드(기존 protection.cir 모델) | 1=G, 2=D, 3=S |
| Amplifier_Operational TL072(값 OPA2992) | 유닛 1·2를 각각 `opamp_rr` 또는 `opamp_rr_noise` 인스턴스로, 유닛 3은 전원 핀 | 유닛 1: 3=+, 2=-, 1=출력. 유닛 2: 5=+, 6=-, 7=출력. 8=V+, 4=V- |
| Regulator_SwitchedCapacitor LT1054 | `lt1054_behavioral` 부분회로 | 8=VIN, 2=CAP+, 3·5=GND |
| Relay_DPDT TQ2-9V | 이상 스위치 2극. 상태는 테스트벤치 파라미터 `k1_on`(0 또는 1). 코일은 579Ω 저항 | 11·21 공통, 12·22 NC, 14·24 NO, A1·A2 코일 |
| R_Potentiometer | 저항 2개. 와이퍼 위치 파라미터 `pos_<지정자>`(0~1, 기본 0.5) | 1, 2=와이퍼, 3 |
| Conn_01x40 (Seed3) | 생성하지 않는다. 테스트벤치가 모듈 스텁(코덱 입력 5kΩ 부하, 출력 DC 1.65V 소스, VIN 부하)을 넷에 붙인다 | |
| AudioJack2, Barrel_Jack, SW_Push, PWR_FLAG | 생성하지 않는다. 테스트벤치가 구동 | |

매핑에 없는 심볼이 BLOCKS에 나오면 생성기는 실패한다. 값 문자열은 R(Ω), k, M, u, n, p 접미사를 파싱하고,
파싱하지 못하면 실패한다.

### 3.3 기존 테스트벤치 이전

| 파일 | include할 블록 | 이전 확인 |
|---|---|---|
| protection.cir | A | 회로 설계 12절 보호 3행과 같은 값 |
| doubler.cir | B | 레일 평균, 리플, 기동 시간 |
| output_stage.cir | E | 레일 16.9V·16.1V 스윙 |
| boot.cir | B, E | OUT_C -60dBu 도달 시각 |
| dc_polarity.cir | B, D, E | 극성 C 전위 |
| cable_ti.cir | E (op-amp만 TI 모델로 바꾸는 옵션) | 계단 응답 과도 |

이전한 테스트벤치의 meas 값이 12절 표와 다르면 원인(손으로 적은 사본과 BLOCKS의 차이, 또는 이전 오류)을
밝힌 뒤에 12절을 고친다. 사본과 BLOCKS가 다른 값은 BLOCKS가 맞다.

### 3.4 몬테카를로

`monte_carlo.py`가 BLOCKS 값에 공차를 적용한 넷리스트를 N벌 만들고 ngspice 배치 모드로 돌려 meas 값을 모은다.

| 변수 | 분포 |
|---|---|
| 저항 | 균일 ±1% (MFR-25). 3.3Ω만 ±5% (CFR-25) |
| 필름·세라믹 커패시터 | 균일 ±10% (C0G C23만 ±5%) |
| 전해 커패시터 | 균일 ±20% |
| 어댑터 전압 | 균일 8.7~9.6V |
| 쇼트키 순방향 전압 | 모델 IS를 순방향 강하 0.25~0.45V(1mA 부근)가 되게 균일 |
| LT1054 손실 | 동작 모델 온저항 균일 7.9~12.7Ω. 10mA 손실이 데이터시트 값 0.35~0.55V가 되는 범위다. 데이터시트 값은 인버터 구성에서 쟀고 다른 구성은 손실이 더 클 수 있다고 적혀 있어, 기존 모델 25Ω(10mA 손실 약 1.05V) 고정을 보수 시나리오(`--conservative`)로 함께 돌린다 |

허용차 값은 부품표(1단계 계획 Task 1)의 품번 사양을 따른다. 사양과 다르면 사양 쪽으로 고친다.

보는 값과 판정:

| 값 | 판정 기준 | 근거 |
|---|---|---|
| 아날로그 레일 최솟값 | 16.1V 이상 | 설계서 4.2절 |
| 패드 비율 | -15 ±1.5dB 안 | 설계서 T5 |
| 출력단 클립 직전 스윙 | +16.5dBu 이상 | 설계서 T6 |
| Vbias / 레일 | 0.5 ±2% | 대칭 스윙 |

N 기본값은 200이다. 출력은 각 값의 최솟값, 1·50·99 백분위, 판정 미달 개수다.

## 4. 도구 1: 잡음 예산

### 4.1 op-amp 잡음 모델

`opamp_rr_noise.inc`는 `opamp_rr`의 동작에 입력 전압 잡음원과 입력 전류 잡음원 2개를 더한다. OPA2992 데이터시트의
전압 잡음은 1kHz 7nV/√Hz, 10kHz 4.4nV/√Hz이고 전류 잡음은 1kHz 60fA/√Hz다. 1/f 모양은 넣지 않고 백색 전압 잡음
두 값(7n 보수, 4.4n 광대역)으로 범위를 낸다.
ngspice는 저항 열잡음을 자동으로 넣으므로 잡음원 크기는 등가 저항이 아니라 전압원·전류원으로 만든다(잡음
전용 소자를 쓰고 동작점에 영향이 없게 한다). TI PSpice 모델은 ngspice에서 잡음이 수백 배 크게 나와(spice
폴더 README) 쓰지 않는다.

### 4.2 해석

| 경로 | 테스트벤치 | 소스 임피던스 | 출력 노드 |
|---|---|---|---|
| 입력, 잭 단락 | 블록 D + 모듈 입력 스텁 | 0Ω | Seed3 Audio In 1 노드 |
| 입력, 베이스 연결 | 위와 같다 | 패시브 픽업 등가 가정값(직렬 7kΩ·3H, 병렬 600pF, 볼륨·톤 포트 부하 125kΩ). 보유 베이스 실측 전이다 | 위와 같다 |
| 출력 | 블록 E + DAC 소스 스텁(AC 접지) | 모듈 출력 임피던스 미공개라 0Ω과 100Ω 두 조건 | OUT 잭 노드 (K1 켬) |

`.noise`를 20Hz~24kHz, 십진 당 50점 이상으로 돌리고 부품별 기여를 함께 출력한다. `noise_budget.py`가 출력 스펙트럼을
A 가중, 125~8000Hz, 20Hz~20kHz로 적분한다. 가중 함수는 IEC 61672 A 특성 식을 쓴다.

### 4.3 예산표

입력 경로 잡음을 입력 기준으로, 출력 경로 잡음을 유니티 기준으로 바꿔 코덱 바닥과 전력 합산한다.

| 행 | 코덱 ADC·DAC 다이내믹 레인지 |
|---|---|
| 칩 값 | ADC 119dB, DAC 120dB (TI 데이터시트) |
| 칩 값 -10dB | ADC 109dB, DAC 110dB |

열은 입력 쪽 바닥, 출력 쪽 바닥, 합산, A 가중 다이내믹 레인지, T7 구간(설계서 7.3절), 지배 쪽이다.
부품별 기여 상위 5개를 경로마다 함께 적는다. 결과는 회로 설계 12절 잡음 단락을 대체한다.

### 4.4 검증

- 단일 저항 10kΩ 개방 잡음이 이론값 12.9nV/√Hz(300K)와 1% 안에서 맞는다
- 비반전 증폭기(게인 5.7, R7·R8 값)의 출력 잡음이 1.1절 손계산 77.7nV/√Hz와 1% 안에서 맞는다
- A 가중 적분이 백색 잡음에서 125~8000Hz 대비 +2.1dB를 낸다(설계서 4.4절)

## 5. 도구 3: 기구 검사

### 5.1 기준 데이터

`enclosure.py` 안에 데이터를 둔다.

| 데이터 | 내용 |
|---|---|
| 케이스 | 외형 95 × 120 × 56mm(페달파츠 표기, 1590C 클론). 벽 두께, 구배, 내부 높이는 미측정 |
| 부품 | 이름, 타공 지름, 패널 바깥 점유 지름(노브·너트·몸체), 패널 안쪽 몸체 상자(폭·깊이·패널 아래 높이), 값마다 출처(설계서 5.2절, 판매처 표기, 실측) |
| 배치 | 부품, 면(윗면, 입력면, 출력면, 뒷면), 면 중심 기준 x·y(mm) |

미측정 값은 `None`과 출처 "미측정"으로 둔다.

### 5.2 검사

| 검사 | 기준 |
|---|---|
| 패널 바깥 간섭 | 점유 원끼리 겹치지 않음. 노브 점유 원 사이 간격은 6.1mm 이상(설계서 5.2절 중심 간격 25mm에서 노브 지름 18.9mm를 뺀 값) |
| 가장자리 여유 | 점유 원이 사용 면적 안. 사용 면적은 외형에서 벽 두께와 모서리 반경을 뺀 값 |
| 패널 안쪽 간섭 | 몸체 상자끼리 겹치지 않음. 면이 다른 부품(윗면 포트와 옆면 잭)도 3D로 본다 |
| 높이 스택 | 포트 아래 기판까지 12mm(설계서 5.2절)와 Seed3 소켓 스택(설계서 5.3절)이 내부 높이 안 |

### 5.3 출력

- 면별 타공 도면 SVG: 면 외곽, 홀 중심 십자와 지름, 중심 기준 좌표 표
- 검사 보고서(markdown): 검사별 통과·실패, 최소 여유와 그 부품 쌍
- 기판 가용 영역: 케이스 안쪽 바닥 사각형 위에 기판 높이까지 내려오는 부품 몸체 투영을 표시한 SVG. 최종 PCB 외곽선의 입력

`--final`로 실행하면 미측정 값이 하나라도 있을 때 도면을 내지 않고 미측정 목록을 출력한 뒤 실패한다.
`--draft`는 미측정 값을 자리표시 값으로 채워 도면에 "초안" 표시를 넣는다.

### 5.4 첫 배치

설계서 5.2절 스케치를 좌표로 옮긴다. 노브 두 줄(3개·2개) 간격 25mm, LED 8칸과 온 LED, 풋스위치, 윗면 DC 잭과
USB, 좌우 면 IN·OUT 잭. 좌표 값은 첫 실행의 검사 결과를 보고 정하고, 정한 값은 설계서 5.2절에 표로 옮긴다.

### 5.5 페달파츠 타공 전 확인

| 항목 | 이유 |
|---|---|
| 커스텀 타공이 받는 도면 형식과 좌표 기준 | 출력 형식이 이에 맞아야 한다 |
| 1590C 클론 타공 가능 여부 | 계획서 부품 표의 문의 항목 |
| 무타공 케이스를 먼저 받아 벽 두께와 내부 높이를 잴 수 있는지 | `--final`의 전제 |

## 6. 테스트

저장소 루트에서 `python3 -m unittest discover -s effector/hardware/tests -t effector/hardware`로 돌린다. ngspice가 필요한 테스트는 ngspice가 없으면
건너뛰고 건너뛴 사실을 출력한다.

| 대상 | 테스트 |
|---|---|
| 값 파싱 | "4.7k", "10R", "2.2M", "1000u 25V", 파싱 실패 |
| 소자 매핑 | 다이오드·BJT·op-amp 유닛의 핀 순서, 매핑 없는 심볼에서 실패 |
| 넷 보존 | BLOCKS의 넷과 생성 넷리스트 노드 집합이 같음 (생성하지 않는 심볼의 핀 제외) |
| 해석해 대조 | 분압기 DC, RC 1차 차단 주파수 (ngspice) |
| 잡음 | 4.4절 세 항목 (ngspice) |
| 몬테카를로 | 공차 0에서 모든 벌이 공칭 값과 같음, 시드 고정 재현 |
| 기구 | 겹치는 원과 안 겹치는 원, 가장자리 경계, 3D 상자 충돌, `--final` 미측정 차단 |

## 7. 한계

- op-amp, LT1054, MOSFET은 동작 모델이라 절대값은 실제 부품과 다를 수 있다. 판정은 2단계 측정(T1, T6, T7)이 한다
- Seed3 모듈의 실제 단일 입출력 다이내믹 레인지는 공개되지 않았다. 예산표는 4.3절 두 행으로 범위만 낸다
- 차지 펌프 리플이 신호에 섞이는 경로(배선·접지 결합)는 회로도에 없어 해석하지 않는다
- 기구 검사는 원통 몸체를 상자로 잡아 간섭을 과하게 본다. 전선 굽힘과 손이 들어갈 공간은 보지 않는다
