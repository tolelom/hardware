# 분리형 무선 게임 컨트롤러

조이콘 스타일 양손 분리형 무선 게임패드.
부품 기준 문서: [parts/xiao-nrf52840.md](../parts/xiao-nrf52840.md),
[parts/xiao-nrf54lm20.md](../parts/xiao-nrf54lm20.md)
최종 갱신: 2026-08-31

## 무엇을 만드나

좌우가 분리된 무선 게임패드를 만든다.
오른손이 BLE Central로 왼손 입력을 모아 PC에 하나의 HID 게임패드로 보인다.

## 상태

설계는 있고 코드는 아직 없다.
보드 2개의 USB 열거와 부트로더 진입을 확인했다. 값은
[parts/xiao-nrf52840.md](../parts/xiao-nrf52840.md)에 있다.

## 왜 nRF52840인가

기준 보드는 XIAO nRF52840 Sense다. BLE와 IMU, 배터리 충전이 한 보드에 있다.

nRF54LM20A Sense와 기본이 입고 예정이고, 스펙만 보면 이쪽이 컨트롤러에 더 맞다.
GPIO 28개, BLE 6.0, nPM1300 PMIC, RAM과 NVM 2배다.
GPIO는 브레드보드에서 쓸 수 있는 수가 다르다. 아래 GPIO 예산 절에 있다.
Sense와 기본 조합은 좌우 분리에도 정확히 맞는다. IMU 있는 쪽과 없는 쪽이다.

그런데도 nRF52840으로 먼저 만든다. 이유는 스택 리스크다.

설계가 지목한 ZMK가 nRF54L 계열에서 도는지 확인되지 않았다.
ZMK 공식 하드웨어 문서에 nRF54L 지원 표기가 없다. Zephyr와 nRF Connect SDK는 지원한다.

nRF52840은 ZMK와 CircuitPython, Zephyr가 모두 검증된 플랫폼이다.
여기서 동작을 먼저 확정해두면 LM20으로 옮길 때 문제가 나도
칩이나 스택 때문인지 내 코드 때문인지 즉시 갈린다.
신형부터 시작하면 그 구분이 안 돼 시간이 갈린다.

LM20은 도착 후 판단한다. 52840에서 만든 것은 버려지지 않고 대조군이 된다.

## GPIO 예산

XIAO nRF52840의 노출 GPIO는 11개다. 칩은 48핀이지만 폼팩터에서 11개만 나온다.
설계된 버튼 배치를 그대로 직결하면 이렇게 된다.

| | 버튼 | 조이스틱 X/Y | 합계 | 여유 |
|---|---|---|---|---|
| 왼손 (L1, L2, -, 스틱 클릭) | 4 | 2 (아날로그) | 6 / 11 | 5 |
| 오른손 (R1, R2, +, A, B, X, Y, 스틱 클릭) | 8 | 2 (아날로그) | 10 / 11 | 1 |

아날로그는 6채널 중 2개만 쓰므로 문제없다.
오른손이 11핀 중 10핀을 쓰므로 여유가 1핀이다.

성립은 하지만 확장 여지가 없다.
진동 모터나 추가 버튼, 배터리 전압 측정을 넣을 자리가 없다.

배터리 전압을 읽는 전용 경로가 XIAO에 있는지는 모름. 확인이 필요하다.
GPIO를 하나 더 써야 한다면 오른손은 그 시점에 핀이 모자란다.

대안이 있다. 오른손 8버튼을 3×3 매트릭스로 스캔하면 6핀으로 줄어 여유가 3핀이 된다.
단 게임패드는 동시 입력이 많아 다이오드가 필수고 회로가 복잡해진다.
직결로 시작하고 핀이 모자랄 때 전환한다.

nRF54LM20A는 GPIO가 28개지만 그중 관통홀로 나오는 수는 확인되지 않았다.
캐스털레이티드 패드에 있는 핀은 브레드보드 단계에서 쓸 수 없다.
[parts/xiao-nrf54lm20.md](../parts/xiao-nrf54lm20.md) 제약 4에 있다.

## 배우는 것과 쓰는 것

배우는 것: USB HID 디스크립터, BLE HID 프로파일, BLE Central과 Peripheral 이중 역할,
IMU 자세 계산(Madgwick), 저전력 설계, KiCad PCB. PCB는 TKL 키보드와 공유한다.

쓰는 것: 게임용 컨트롤러다.
다만 기성품이 이미 잘 만들어져 있어 실사용 가치는 키보드보다 낮다.
이것은 인정하고 간다. 여기서 얻는 주요 가치는 배움 쪽이다.

## 시스템 구성

```
[왼손]                              [오른손]
XIAO nRF52840                       XIAO nRF52840 Sense
 +- 버튼 L1, L2, -                   +- 버튼 R1, R2, +, ABXY
 +- 조이스틱 L                        +- 조이스틱 R
 +- IMU 없음. 논-Sense                +- IMU LSM6DS3TR-C
 +- LiPo                             +- LiPo
 +- BLE Peripheral ---- BLE ---->    +- BLE Central
                                          |
                                          +--> PC. 단일 HID 게임패드
```

현재 보유분이 Sense 1개와 논-Sense 1개이므로 IMU는 오른손에만 둔다.
정식 구성에서는 양손 모두 IMU를 갖는다.

## 단계

| # | 단계 | 판정 기준 |
|---|---|---|
| 0 | 보드 첫 구동. 툴체인 하나 확정 | 직접 올린 코드로 LED가 깜빡이고 시리얼에 출력이 나온다. 공장 펌웨어도 LED를 순환시키므로 LED만으로는 판정하지 않는다. `parts/xiao-nrf52840.md` 툴체인 표를 검증됨으로 갱신 |
| 1 | 유선 USB HID. 버튼 1개 | PC가 게임패드로 인식하고 게임패드 테스터에 버튼 입력이 뜬다 |
| 2 | 유선 HID 전체. 오른손 8버튼과 조이스틱 | 전 입력이 테스터에 정확히 매핑된다. 채터링이 없다 |
| 3 | BLE HID 단일. 오른손만 무선 | 케이블을 뽑고 PC에 게임패드로 붙어 2단계와 동일하게 동작한다 |
| 4 | BLE 분리형. 왼손 Peripheral에서 오른손 Central로 | 양손 입력이 하나의 게임패드로 PC에 도달한다. 왼손 지연을 측정해 오른손과 비교한다 |
| 5 | IMU 연동 | 보드를 기울이면 축 값이 따라 움직인다 |
| 6 | 배터리 구동 | USB 없이 동작하고 USB 연결 시 충전된다 |
| 7 | PCB 설계와 케이스 | 별도 판단. 3D 프린터가 필요하다 |

1에서 2, 3으로 가는 순서가 핵심이다.
유선에서 HID를 먼저 확정하면 무선에서 문제가 났을 때 HID 문제가 아님이 이미 증명돼 있다.

4단계의 지연은 좌우가 비대칭이다. 왼손 입력만 BLE 홉을 하나 더 거치기 때문이다.
BLE는 connection interval마다 통신 기회가 오고 그 최소값이 7.5 ms이므로 홉마다 대기가 붙는다.
절대 지연보다 좌우 차이가 조작에서 먼저 드러나므로 4단계에서 이것을 측정한다.

측정은 추가 장비 없이 된다. 왼손이 패킷을 보내고 오른손이 즉시 에코하면 왼손에서 왕복 시간을
잴 수 있고, 그 절반이 편도 추정치다. connection interval을 바꿔가며 비교하면 설정이 실제로
적용됐는지도 함께 확인된다.

## 부품

### 프로토타입

지금 시작 가능한 구성이다.

| 부품 | 수량 | 보유 |
|---|---|---|
| XIAO nRF52840 Sense | 1 | 있음 |
| XIAO nRF52840 (논-Sense) | 1 | 있음 |
| 6mm 택트 스위치 (DIP) | 20 | 없음. 약 ₩2,000 |
| KY-023 조이스틱 모듈 | 2 | 없음. 약 ₩3,000 |
| 미니 브레드보드 | 2 | 있음 |
| 점퍼 와이어 M-M | 1묶음 | 있음 |
| USB-C 케이블 | 1 | 있음 |
| LiPo와 JST 1.25mm 2핀 300mAh | 2 | 없음. 6단계까지 불필요 |

0단계에서 5단계까지는 USB 전원으로 전부 진행된다. 배터리는 6단계에서 필요하다.
Alps SKRPACE010은 SMD라 프로토타입에 못 쓴다. DIP 택트 스위치를 쓴다.

### 정식 제작

| 부품 | 규격 | 수량 | 비고 |
|---|---|---|---|
| XIAO nRF52840 Sense | - | 2 | 1개 추가 필요 |
| Alps SKRPACE010 | 저프로파일 1.5mm | 15~20 | 여유분 포함. 실사용 12개 |
| Alps RKJXV 시리즈 | 아날로그 | 2 | 구하기 어려우면 Switch 호환 모듈으로 대체 |
| LiPo | JST 1.25mm 2핀, 300~500mAh | 2 | JST PH 2.0mm가 아니다. 주의 |
| 슬라이드 스위치 | SS12D00G3 | 2 | 전원 ON/OFF |
| 커스텀 PCB | - | 2 | KiCad로 설계해 JLCPCB 발주 |
| M2 나사 | 4~6mm | 여러 개 | 케이스 고정 |
| PLA 필라멘트 | - | - | 3D 프린터 필요 |

예상 비용은 프로토타입 약 ₩54,000, 정식 약 ₩80,000이다.
보유분을 빼면 프로토타입은 약 ₩5,000이다.

구매처: Seeed 공식(XIAO), 디바이스마트(Alps 버튼, 조이스틱, 스위치),
엘레파츠(배터리, 브레드보드), 알리(KY-023, 택트스위치. 배송 2~3주), JLCPCB(PCB).

### IMU 선택 근거

설계 시 검토 결과다.

| | LSM6DS3TR-C (내장) | ICM-42688-P |
|---|---|---|
| 자이로 노이즈 | 7 mdps/√Hz | 2.8 mdps/√Hz |
| 가속도 노이즈 | 90 μg/√Hz | 70 μg/√Hz |
| 조이콘 수준 용도 | 충분 | 과분 |
| VR 수준 정밀 트래킹 | 부족 | 적합 |

내장 IMU로 간다. 부족하면 ICM-42688을 SPI로 추가할 핀 여유는 있다.

## 소프트웨어 방향

설계 시 결정한 것이다.

| 항목 | 선택 | 비고 |
|---|---|---|
| 펌웨어 1단계 | CircuitPython과 BLE HID 라이브러리 | 빠른 검증용 |
| 펌웨어 2단계 | ZMK로 포팅 | 분리형 BLE가 검증된 스택. 저지연 |
| RTOS | Zephyr | nRF52840 공식 지원. ZMK의 기반 |
| 자세 계산 | Madgwick 필터, 쿼터니언 | 경량이라 MCU에 적합 |
| 제스처 인식 | 규칙 기반으로 시작해 DTW로 | 단계적으로 고도화 |
| 핑거트래킹 | 미채택 | 게임 연동 복잡도가 과다하다고 판단 |

ZMK로 가는 2단계는 nRF54LM20 이관 여부와 얽혀 있다.
ZMK의 nRF54L 지원이 확인되지 않았으므로 LM20으로 옮길 경우 이 항목을 다시 판단한다.

## 지금 없는 것

| 항목 | 리드타임 |
|---|---|
| 택트 스위치, KY-023 | 알리 2~3주, 국내 며칠 |
| XIAO nRF52840 Sense 1개 (정식 구성) | - |
| LiPo, JST 1.25mm | 6단계 전까지 불필요 |
| 3D 프린터 | 7단계 전까지 불필요. 미보유 |

0단계는 지금 가진 것만으로 시작된다.
스위치가 없어도 점퍼선을 GPIO와 GND에 단락시키면 입력 흉내는 난다.
다만 채터링 특성이 달라 2단계 디바운싱 검증에는 실제 스위치가 필요하다.

## 그만둘 조건

- 1단계(유선 USB HID 인식)를 두 개 스택으로 시도해도 못 넘기면 중단하고 막힌 지점을 기록한다.
  예를 들어 CircuitPython과 Zephyr다. 여기서 막히면 그 위 단계는 전부 무의미하다.
- nRF54LM20 도착 후 LM20에서 ZMK나 Zephyr 스택이 확인되면 52840 트랙을 접고 옮기는 것을 검토한다.
  이때 52840에서 확정한 HID 디스크립터와 입력 로직은 그대로 가져간다.
- 3D 프린터가 없는 한 7단계는 시작하지 않는다. 6단계에서 멈추고 브레드보드 상태로 남겨도 된다.
